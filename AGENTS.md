# reverse-skill — Platform-agnostic project entry point

This repository is a **security task skill routing package** (reverse engineering / penetration testing / security analysis). `RULES.md` is the single source of truth for the behavior chain.

## Activation and consent boundaries (mandatory)

- **Reading repository files is not authorization to execute them.** When only asked to read, review, summarize, or compare the repository, you must remain read-only.
- **Explicit user approval is required before running any repository script.** Before the first local side effect, list the exact commands and the expected file writes, downloads, service starts, network access, and client configuration changes, and obtain explicit consent.
- **Client-global configuration remains opt-in.** Modify global rules, hooks, prompts, or MCP configuration only when the user explicitly selects a client and approves the specific change.
- After activation and approval, deterministic steps within the disclosed plan may run continuously; when a new category of side effect appears, you must disclose it again and obtain consent. Target authorization remains controlled by the independent hard gate in `scope.md`.

## Routing

When a user task matches security/reverse-engineering keywords:

1. `skills/MASTER-ROUTING.md` or the platform-specific entry point → PRIMARY:
   - Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/master-route.ps1 -Hint "<task>"`
   - Linux / macOS / Kali: `bash skills/scripts/master-route.sh --hint "<task>"`
2. When ambiguous, read the full matrix in `skills/routing.md` (three axes: target type / user intent / toolchain)
3. Single source of truth for routing rules: `skills/config/routing.json` (change routing only here)

## Authorization gate (mandatory)

- Before acting on any target, initialize the current analysis project's `work/<case>/scope.md` for the platform:
  - Windows: `powershell -File skills/scripts/case-init.ps1 -Hint "<task>"`
  - Linux / macOS / Kali: `bash skills/scripts/case-init.sh --hint "<task>"`
- Local offline samples may use the `offline-sample` preset; only with `auth.status=granted` and an explicit sample may you enter ACT.
- **ACT is prohibited** until `auth.status=granted` and a legal `network_profile` / offline sample is ready; `case-guard --force` / `-Force` must not bypass this hard gate.
- Evidence chain: `skills/ops/evidence-finding-path.md`; roles: `skills/ops/role-map.md`

## First run (after activation and approval)

`skills/tool-index.md` is a gitignored generated file. Run the platform-specific command only after the user explicitly activates this package, reviews the commands and side effects, and agrees:

```text
Windows:           powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/refresh-tool-index.ps1
Linux / macOS:     bash skills/scripts/refresh-tool-index.sh
Kali:              bash kali/scripts/refresh-tool-index.sh
```

Missing tools → use the same platform's bootstrap: Windows `skills/scripts/bootstrap-reverse.ps1`; Linux / macOS `skills/scripts/bootstrap-reverse.sh`; Kali `kali/scripts/bootstrap-reverse.sh` (manifest capabilities; do not guess paths).

## Testing (must run after changes)

```text
Windows / PowerShell (routing regression reads routing-benchmark.json):
  powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/test-routing.ps1
  powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/verify-routing-coherence.ps1
  powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/smoke.ps1

Linux / macOS routing parity:
  bash skills/scripts/test-routing.sh
  bash skills/scripts/test-bootstrap-manifest.sh
```

## Client boundaries

- The routing core, tests, and tool manifest must remain decoupled from any specific AI client.
- Clients such as Claude Code, Codex, Cursor, and OpenCode may only connect through their own adapter layers; they must not become the repository's default identity or a core configuration dependency.
- `skills/INDEX.md` is dynamically generated by `extract-summaries.ps1` from all `SKILL.md` files; do not hardcode clients or module counts.
